# Execution plans

Keep one active plan in `CURRENT_PLAN.md`. For a significant milestone record its objective, architecture, dependencies, acceptance checks, decisions, risks, completed work and next step. Prefer concrete commands and observed results over promises.

Use these states: proposed, implementing, ready for user review, user accepted, merged. Passing tests permits review, not acceptance. Record the feature branch and unresolved problems. Update the plan as facts change; avoid a separate planning framework.
